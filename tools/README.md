## Qué es este registro

Este archivo ordena las herramientas vinculadas a **SERENA™ / SERENA SIRENA™** en dos planos distintos:

1. **Ecosistema público Serena / MCP / GitHub:** herramientas externas que ya circulan con el nombre Serena dentro de repositorios, MCP servers y agentic workflows.
2. **SERENA™ oficial de Valeria Saa:** identidad conceptual, mapa de herramientas, documentación, mediación, workflows, publicación y futura capa/plugin propio.

La intención es construir una puerta clara: si alguien pregunta “¿dónde están las herramientas Serena?”, este registro responde qué existe, qué es externo, qué es nuestro y qué falta construir oficialmente.

## Herramientas externas llamadas Serena

En el ecosistema técnico público, **Serena** aparece como un MCP toolkit para agentes de código. Según la documentación pública revisada, ese Serena externo ofrece herramientas semánticas de análisis, navegación y edición de código.

Ejemplos de herramientas mencionadas en documentación pública:

| Categoría | Herramientas |
|---|---|
| Navegación de símbolos | `find_symbol`, `find_referencing_symbols`, `get_symbol_definition`, `list_symbols_in_file` |
| Edición de código | `replace_symbol_body`, `insert_after_symbol`, `insert_before_symbol`, `delete_symbol` |
| Análisis de proyecto | `find_files`, `get_project_structure`, `analyze_imports` |

**Importante:** estas herramientas pertenecen al ecosistema técnico externo donde hoy circula Serena como MCP server / workflow. No se presentan aquí como código propio de Valeria Saa.

## Qué sería el plugin oficial SERENA™

El plugin oficial debería funcionar como una capa de entrada para el **Modo Serena**:

- ordenar identidad, autoría y contexto;
- activar herramientas de documentación y trazabilidad;
- conectar GitHub, web, press kit, social kit y NFT metadata;
- ofrecer workflows para agentes y MCP;
- separar lo confirmado, lo pendiente y lo inferido;
- producir salidas públicas claras: post, issue, nota, manual, ficha técnica, registro.

## Primer MVP del plugin

El primer MVP no necesita resolver todo. Tiene que hacer tres cosas muy bien:

1. **Identificar:** qué material pertenece a SERENA™ / SERENA SIRENA™.
2. **Ordenar:** convertir conversaciones, archivos y evidencia en documentación clara.
3. **Publicar:** preparar README, post, nota de prensa, social kit, metadata y links.

## Reglas de oficialidad

Para que algo sea considerado oficial SERENA™ / SERENA SIRENA™ dentro de este repo debe cumplir:

- estar documentado en `valeriasaa-lgtm/SERENA`;
- tener atribución clara a Valeria Saa cuando corresponda;
- separar código externo, inspiración, integración y obra propia;
- no publicar secretos, contraseñas, tokens, claves privadas ni datos sensibles;
- tener una función clara dentro del mapa SERENA;
- poder ser explicado a una persona no técnica.
